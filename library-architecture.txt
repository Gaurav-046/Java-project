Library Management System - Complete Architecture Documentation
================================================================

1. OVERVIEW
----------------------------------------------------------------
The Library Management System is a full-stack application consisting of:
- Java HTTP server (JDK 17 built-in com.sun.net.httpserver)
- Vanilla JavaScript frontend (web/index.html, no build step required)
- PostgreSQL database backend
- RESTful JSON API over HTTP on port 8080

2. SERVER ARCHITECTURE
----------------------------------------------------------------
2.1 Java HTTP Server (JDK 17 Built-in)
- Uses com.sun.net.httpserver.HttpServer class
- No external web server required (Tomcat, Jetty, etc.)
- Embedded in the uber-jar: target/library-system-1.0-SNAPSHOT-shaded.jar
- Simple routing: Main.java creates HttpServer on port 8080
- Each URL path maps to a specific handler class

2.2 Request Processing Pipeline
Every incoming request follows this path:
1. Cors.handle(ex) - Checks for OPTIONS preflight, returns 204 with CORS headers
2. Auth.session(ex) - Validates session token from Authorization: Bearer <token>
3. Method validation - Ensures HTTP method allowed for endpoint
4. Body parsing - Json.read(ex, Class) reads/parses request body as UTF-8
5. DAO operation - Database interaction via JDBC
6. Error handling - DbErrors.wrap() translates SQL constraints to HTTP 409/500
7. Response - JSON body with Content-Type: application/json; charset=UTF-8

2.3 Main.java Entry Point
- Creates HttpServer on port 8080
- Registers /api/* contexts to ApiRouter
- Default handler returns 404 for unmatched paths

3. DATABASE CONNECTIVITY
----------------------------------------------------------------
3.1 DBConnection.java
- Manages database connections via DriverManager.getConnection()
- Default URL: jdbc:postgresql://localhost:5432/library_db
- Overridable via environment variables: DB_URL, DB_USER, DB_PASSWORD
- Explicit driver registration: Class.forName("com.mysql.cj.jdbc.Driver")
- Auto-commit: Disabled for transactional operations

3.2 Environment Variables (set for PostgreSQL)
setx DB_URL "jdbc:postgresql://localhost:5432/JAVA"
setx DB_USER "postgres"
setx DB_PASSWORD "root"

3.3 PostgreSQL Schema (schema-postgres.sql)
Five tables:

books:
- id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
- title VARCHAR(200) NOT NULL
- author VARCHAR(100) NOT NULL
- isbn VARCHAR(20) UNIQUE
- publish_year INT
- genre VARCHAR(50)
- "condition" VARCHAR(20) NOT NULL DEFAULT 'Available'
- total_copies INT NOT NULL DEFAULT 1
- available_copies INT NOT NULL DEFAULT 1

librarians:
- id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
- username VARCHAR(50) NOT NULL UNIQUE
- password_hash VARCHAR(255) NOT NULL
- full_name VARCHAR(100) NOT NULL
- role VARCHAR(20) NOT NULL DEFAULT 'LIBRARIAN'

members:
- id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
- name VARCHAR(100) NOT NULL
- email VARCHAR(120)
- phone VARCHAR(30)
- active_status BOOLEAN NOT NULL DEFAULT TRUE

issue_records:
- id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
- book_id INT NOT NULL FK → books(id) ON DELETE CASCADE
- member_id INT NOT NULL FK → members(id) ON DELETE CASCADE
- issue_date DATE NOT NULL
- due_date DATE NOT NULL
- return_date DATE
- status VARCHAR(20) NOT NULL DEFAULT 'ISSUED'
- fine_amount DECIMAL(10,2) NOT NULL DEFAULT 0

activity_logs:
- id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
- librarian_id INT FK → librarians(id) ON DELETE SET NULL
- action VARCHAR(50) NOT NULL
- details VARCHAR(255)
- timestamp TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP

3.4 Seed Data
Two default accounts (passwords are PBKDF2-HMAC-SHA256):
- admin / admin123 (role: ADMIN)
- librarian / librarian123 (role: LIBRARIAN)

4. AUTHENTICATION & SESSION MANAGEMENT
----------------------------------------------------------------
4.1 Token-Based Authentication
- Stateless session tokens (UUIDs) rather than server-side sessions
- 8-hour TTL (Time To Live)

4.2 Login (POST /api/login)
- Body: {"username": "...", "password": "..."}
- Success: {"token": "uuid", "librarian": {"id": N, "username": "...", "fullName": "...", "role": "..."} }
- Failure: 401 {"error": "Invalid username or password"}
- Failed logins audited; timing-equalizer defense (same cost whether username exists or not)

4.3 Session Creation (SessionManager.create())
public static Session create(Librarian librarian) {
    String token = UUID.randomUUID().toString();
    SESSIONS.put(token, new Entry(session, System.currentTimeMillis() + TTL_MILLIS));
    return new Session(token, librarian.id(), librarian.username(), librarian.fullName(), librarian.role());
}

4.4 Token Validation (SessionManager.get(token))
- Checks token exists, is not expired (8-hour TTL), removes expired entries
- Returns null for missing/expired → handlers respond with 401

4.5 Logout (POST /api/logout)
- Invalidates token: SESSIONS.remove(token)
- Returns 200 {"message": "Logged out"}

4.6 Password Storage
- PBKDF2-HMAC-SHA256 with 210000 iterations
- Format: pbkdf2$210000$saltBase64$hashBase64
- Dummy hash used when username doesn't exist (enumeration resistance)

5. CORS (Cross-Origin Resource Sharing)
----------------------------------------------------------------
5.1 Cors.java - Preflight Handler
All API handlers call Cors.handle(ex) first:

static boolean handle(HttpExchange ex) throws IOException {
    ex.getResponseHeaders().set("Access-Control-Allow-Origin", "*");
    ex.getResponseHeaders().set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS");
    ex.getResponseHeaders().set("Access-Control-Allow-Headers", "Content-Type, Authorization");
    
    if ("OPTIONS".equals(ex.getRequestMethod())) {
        ex.sendResponseHeaders(204, -1);
        ex.close();
        return true;  // Preflight handled
    }
    return false;  // Continue with normal processing
}

5.2 What This Enables
- Browser-based frontend can call API from localhost origin
- All methods (GET, POST, PUT, DELETE, OPTIONS) permitted
- Content-Type and Authorization headers allowed
- No CORS errors when website fetches from http://localhost:8080

7.2 API Utility Function
async function api(path, opts = {}) {
    var headers = {};
    if (state.token) headers['Authorization'] = 'Bearer ' + state.token;
    if (opts.body && !opts.headers['Content-Type']) 
        opts.headers['Content-Type'] = 'application/json';
    var res = await fetch(path, {...opts, headers});
    return {...res, ok: res.ok, status: res.status, json: async () => await res.json(), text: async () => await res.text()};
}

7.3 Key Frontend Flows

8. TRANSACTION MANAGEMENT
----------------------------------------------------------------
8.1 Issue Flow (IssueDAO.issue())
All database operations in single transaction:
java
try (Connection conn = DBConnection.getConnection()) {
    conn.setAutoCommit(false);  // Start transaction
    
    Member member = memberForIssue(conn, memberId);
    Book book = bookForIssue(conn, bookId);
    requireUnderLimit(conn, memberId);
    
    // Decrement stock, guard against oversell
    UPDATE books SET available_copies = available_copies - 1 WHERE id = ? AND available_copies > 0
    
    INSERT INTO issue_records (...) VALUES (..., 'ISSUED', 0)
    
    conn.commit();  // Commit
} catch (Exception e) {
    rollback(conn);  // On failure
}

8.2 Return Flow (IssueDAO.returnBook())
Similarly atomic:
1. Compute overdue fine (whole days × $0.50/day)
2. Update issue_record with return_date and status 'RETURNED'
3. Increment book stock (guard: available_copies < total_copies)
4. Commit

9. ERROR HANDLING
----------------------------------------------------------------
9.1 DbErrors.java - SQL Exception Translation
Maps SQL states to HTTP responses:

| SQLState | Error Code | HTTP | Message |
|----------|-----------|------|---------|
| 23 (integrity) | 1062 | 409 | "This X clashes with existing record" |
| 23 | 1451 | 409 | "Cannot delete/change: other records reference it" |
| 23 | 1452 | 409 | "Cannot save: referenced record does not exist" |
| 23 | 1048 | 409 | "A required value is missing" |
| Other 23 | - | 500 | Database error detail |
| Non-23 | - | 500 | Generic database error |

9.2 CirculationException
IssueDAO.CirculationException carries HTTP status and message:
- 409: "No copies available", "Borrowing limit reached", "Member is not active"
- 404: "Member not found", "Book not found", "Issue record not found"
- 500: Database errors

12. KEY TECHNOLOGY DECISIONS
----------------------------------------------------------------
- **No build step for frontend**: web/index.html served directly, vanilla JS
- **JDK built-in HTTP server**: No external web server required
- **PostgreSQL over MySQL**: Chosen for better JSON support and modern features
- **Token-based auth over session cookies**: Simpler, no CSRF concerns
- **CORS prehandled in every handler**: Consistent, no framework middleware needed
- **Transactions only for writes**: Reads can be autocommit for simplicity
- **Soft delete for members**: Preserves circulation history
- **Condition as separate endpoint**: Prevents inconsistent stock/condition states

13. TROUBLESHOOTING
----------------------------------------------------------------
12.1 Server won't start: "Address already in use"
- Kill existing java process or change port in Main.java
- Windows: taskkill /IM java.exe /F
- PowerShell: Get-Process java* | Stop-Process -Force

12.2 Login fails with "Invalid username or password"
- Verify DB_PASSWORD env var matches PostgreSQL
- Ensure seed data inserted via schema-postgres.sql
- Check case sensitivity of username

12.3 CORS errors in browser
- Ensure every handler calls Cors.handle(ex) first
- Verify Access-Control-Allow-Origin: * is set

12.4 Database connection fails
- Confirm PostgreSQL is running (port 5432)
- Verify DB_URL, DB_USER, DB_PASSWORD environment variables
- Test with: psql -U postgres -h localhost -d JAVA

12.5 "Method not allowed" on valid routes
- Ensure correct HTTP method (GET/POST/PUT/DELETE)
- Check Cors.handle() isn't returning prematurely
- Verify Authorization header format: "Bearer " + token

12.6 Book issue says "Member is not active"
- Member.active_status = false in database
- Reactivate with: PUT /api/members/{id} {activeStatus: true}

12.7 Returns compute incorrect fines
- Verify due_date calculation (issue_date + 14 days)
- Fine rate: $0.50 per whole day late
- computeFine() in IssueDAO uses ChronoUnit.DAYS.between()
